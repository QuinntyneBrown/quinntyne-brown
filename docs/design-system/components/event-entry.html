Event entry

One event an application sent, as a disclosure whose body shows its fields or its raw JSON.

WCAG 2.2 AAStatus: new

Overview

An event entry is one row of an application’s events list: a button with the event’s kind, who or what it is about, and when it arrived, that expands to show the event. Contact requests show their fields in a description list; any other event type shows its data as JSON in a code block, so new event types appear before they have a view of their own.

    Ada Lovelace
    Email
    ada@example.com
    Message
    We’d like to talk about volunteering at the next hackathon.
    Received
    Today, 2:58 pm

Anatomy

  1. ToggleA button inside a level-3 heading, aria-expanded and aria-controls.
  2. TitleA badge for the kind, then the person’s name or the event type.
  3. Meta and previewEmail and received time; collapsed entries add the first line of the message.
  4. BodyA description list, or a code block for other types.

Variants

Two bodies: contact request (fields) and other (JSON).

  • {
  "email": "mira@example.com"
}

Sizes

One size; fills the list width.

Hover tints the toggle with --color-bg-subtle-hover; focus shows the focus ring; the chevron turns when open (no motion with reduced motion).

Responsive behaviour

The description list keeps its two columns from 360px; long emails and event IDs wrap anywhere; the JSON block scrolls sideways inside itself.

Theming

Surface, border and text tokens only; the badges carry their own pairs. No new tokens.

Accessibility

  • The toggle is a real button in a heading, so the list can be browsed by heading and each entry announces expanded or collapsed.
  • Email and phone are links (mailto:, tel:).
  • The message keeps its line breaks and is never truncated when open.

Content

  • Kinds: “Contact request”, “Other event”.
  • Times: “Today, 2:58 pm”, “Mon 20 Oct, 4:05 pm”.
  • Other: “This kind of event has no view of its own yet. Its data is shown as sent.”
